## Checked, no finding
- **`tries` in `subjectQuizSummary`**: it sums `q.tries` over the `quizzes` that `shelf(repo, subjectId)` already returns for the Quizzes tile. No new query: `shelf` reads through the student's own `Repo` (RLS-scoped in Supabase, per-user in demo), so it's owner-scoped like `best` and `unfinished` next to it. The subject page calls it after loading the subject through the same repo (another student's id is a 404).
- **Server actions**: no new action, no new argument. `src/server/actions/sources.ts` changes two error strings only. `getDownloadUrl` (unchanged) checks the id with zod, reads the source through the student's repo, refuses files still being checked, and signs for 60 s with `download` set.
- **Open-file fallback and open redirect**: both callers pass only `res.url` from `getDownloadUrl` (source page adds `#page=<number>` from the server-side `markedPage`). No query parameter, hash or user text reaches the URL, so there's no open redirect. The new tab no longer gets `noopener` as a feature (it makes `window.open` return null); `opener` is set to `null` right after, and the tab is a Supabase Storage attachment (or our own attachment route), which runs no script. `Referrer-Policy: strict-origin-when-cross-origin` means Supabase sees only our origin, as before.
- **XSS**: no new `dangerouslySetInnerHTML`, `innerHTML`, `javascript:` or URL built from user text. New text output (subject names in `SubjectChip` with a `title` attribute, file names with `title`, `NoSources`, `StartHere`, `nextDueLine`) is React-escaped. `subjectStyle` and the tile `--r` values set CSS custom properties from the `SubjectColour` enum and constants only.
- **Time zone in `nextDueLine`**: the zone comes from `DayContext.tz`, which is `safeTimeZone(profile.timezone)` (S4-4), so a bad stored value can't make `Intl` throw on the Flashcards page.
- **Links added**: `NoSources` links to `/subjects/<id>#files-h` with the server-loaded subject id; `focusUploads` only scrolls and focuses. Landing copy only changes text.
- **Privacy page**: changes are layout only (44 px link targets); the content still matches the app (export excludes the calendar link and the files themselves; deletion removes files first, then the user, and turns off the calendar link).
- **Test kit, secrets and exposure**: the kit names only the public production URL, no keys, passwords, project refs, SMTP credentials or tester data. Its limits match `src/lib/limits/ai.ts`, and its export and calendar wording matches Settings and the privacy page. The new screenshots in `docs/design/polish-shots/` show demo data only (no emails or real files).
- **Secrets**: a production build with sentinel values for `SUPABASE_SECRET_KEY`, `GROQ_API_KEY`, `CLOUDFLARE_AI_TOKEN` and `EMBED_FUNCTION_SECRET` has none of them in `.next/static`, and neither `calendar_links` nor `token_hash`. No `.env` file is tracked other than `.env.example`.
- **Dependencies**: `package.json` and `package-lock.json` are unchanged. `npm audit --omit=dev`: 0 vulnerabilities. The full `npm audit` still lists the dev-only `braces` advisory (eslint tooling), which was there before.
- **RLS**: no migration in this diff, so `npm run test:db` was not re-run (no `DATABASE_URL` here); the Step 4 results still stand.
